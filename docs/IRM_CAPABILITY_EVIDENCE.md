# IRM capability evidence ledger

This ledger is the authority for comparing Fynix Cyber Audit with the broader [ServiceNow Integrated Risk Management portfolio](https://www.servicenow.com/products/integrated-risk-management.html). It separates implemented behavior from roadmap intent and prevents unsupported parity claims.

## Claim policy

A capability may be described as **implemented** only when this ledger points to all applicable product evidence:

1. a persisted domain model and migration;
2. an authorized operator, REST, or MCP interface;
3. an automated behavior test; and
4. operator documentation for workflows that require it.

Code presence alone is not enough to claim portfolio parity. `docs/plans/` is roadmap material, not product evidence. Partial capabilities must be named narrowly. Missing capabilities must not appear in product or sales copy as available.

## Current defensible product claim

Fynix Cyber Audit implements workflows for **risks, controls, audits, findings, evidence, and remediation**. These workflows can support an IRM program, but Fynix does not currently claim full ServiceNow IRM portfolio parity.

## Parity sequence

Work advances by closing one evidence-complete vertical slice at a time:

1. **Risk portfolio foundation** — delivered: enterprise, operational, and technology risks have domain-aware profiles, accountable owners, appetite thresholds, attributable review snapshots, derived state, issues, scoped UI, REST/MCP detail exposure, and exports; enterprise risks add cycle-safe hierarchy, current active residual-score roll-ups, and versioned deterministic likelihood/impact stress scenarios. Stochastic simulation, calibrated probability, correlation/quantitative loss modeling, external telemetry, upstream review-evidence ingestion, evidence-authenticity validation, and automatic remediation remain.
2. **Policy compliance foundation** — delivered: policy obligations, attributable attestations, exceptions, control mappings, due/overdue status, append-only history through product interfaces, operator UI, REST interface, and documentation. Broader regulatory-change and acknowledgement capabilities remain.
3. **Continuous control testing foundation** — delivered: recurring test definitions, operator/REST observations, optional accepted/authorized audit-evidence links with retained content and provenance/size/SHA-256 snapshots, server-derived threshold results, due state, append-only history through product interfaces, and failed-test findings. External indicator ingestion, background execution, automatic evidence collection, evidence-authenticity/sufficiency validation, and automatic remediation triggers remain; finding lifecycle is delivered in slice 7.
4. **Operational resilience foundation** — delivered: business services, versioned impact analyses, typed dependency maps, recovery plans, scenario exercises with optional accepted/authorized audit-evidence links and retained provenance/size/SHA-256 snapshots, RTO/RPO measurement, derived readiness, and exercise issues. Automated discovery, telemetry, automatic evidence collection, authenticity/sufficiency validation, exercise orchestration, crisis communications, and automatic remediation triggers remain; issue lifecycle is delivered in slice 7.
5. **AI governance foundation** — delivered: AI system inventory, use cases, owners, versioned risk assessments, control/risk mappings, attributable approval snapshots, derived governance state, monitoring reviews with optional accepted/authorized audit-evidence links and retained provenance/size/SHA-256 snapshots, and issues. Automated discovery, regulatory mapping, automatic evidence collection, evidence-authenticity/sufficiency validation, continuous telemetry, runtime enforcement, and automatic remediation remain; issue lifecycle is delivered in slice 7.
6. **Third-party risk foundation** — delivered: existing vendor due diligence joined to versioned risk assessments, governed third-party risk links, attributable decision snapshots, periodic reviews with optional accepted/authorized audit-evidence links and retained provenance/size/SHA-256 snapshots, derived state, and review issues. External intelligence, fourth-party mapping, automatic evidence collection, authenticity/sufficiency validation, automatic reassessment, and automatic remediation remain; issue lifecycle is delivered in slice 7.
7. **Governance issue and remediation lifecycle** — delivered: issues from risk portfolio, third-party risk, AI monitoring, resilience exercises, and continuous control tests register into a shared owner-scoped lifecycle; managers create linked remediation tasks, completed tasks enter verification, independent verifiers close issues, regressions reopen them, and append-only transition snapshots support reporting. Automatic treatment selection/execution, effectiveness telemetry, and automatic closure remain.
8. **Governed closure evidence** — delivered: every issue closure requires accepted audit-evidence attachments accessible to the independent verifier; the server locks evidence state, confirms readable content, creates a bounded retained copy, and records append-only file identity, provenance identities, accepted state, metadata, actual size, copy disk/path, and SHA-256 snapshots through product interfaces. Hashes prove byte identity at closure, not evidence truth, effectiveness, or provenance beyond the accepted audit workflow. Upstream assessment/monitoring evidence ingestion remains separate.
9. **Governed control-test observation evidence** — delivered: an operator or integration recording an observation may bind accepted audit-evidence files it is authorized to access; the server creates bounded retained copies and append-only provenance, metadata, actual-size, disk/path, actor/time, and SHA-256 snapshots exposed through REST and the operator workspace. Evidence selection and observed values remain deliberate inputs; connectors, automatic collection, authenticity/sufficiency validation, and inference from file content remain absent.
10. **Governed AI monitoring evidence** — delivered: an authorized AI-governance manager recording a monitoring review may bind accepted audit-evidence files it is authorized to access; the server creates bounded retained copies and append-only provenance, metadata, actual-size, disk/path, reviewer/time, and SHA-256 snapshots exposed through REST and the operator workspace. Evidence selection and review metrics remain deliberate inputs; connectors, automatic collection, authenticity/sufficiency validation, and metric inference from file content remain absent.
11. **Governed third-party periodic-review evidence** — delivered: an authorized third-party risk manager recording a periodic review may bind accepted audit-evidence files it is authorized to access; the server creates bounded retained copies and append-only provenance, metadata, actual-size, disk/path, reviewer/time, and SHA-256 snapshots exposed through REST and the operator workspace. Evidence selection and review conclusions remain deliberate inputs; external feeds, connectors, automatic collection, authenticity/sufficiency validation, and inference from file content remain absent.
12. **Governed resilience-exercise evidence** — delivered: an authorized resilience manager completing an exercise may bind accepted audit-evidence files it is authorized to access; the server creates bounded retained copies and append-only provenance, metadata, actual-size, disk/path, completer/time, and SHA-256 snapshots exposed through REST and the operator workspace. Evidence selection and measured recovery values remain deliberate inputs; telemetry, connectors, automatic collection, authenticity/sufficiency validation, and inference from file content remain absent.

Each slice updates this ledger in the same commit as its behavior and tests. Product copy changes only after the row reaches **Implemented**.
